## Termos desta aula

- **Tática** — O 'porquê' do atacante (ex.: obter credenciais).
- **Técnica** — O 'como' (ex.: T1110 Brute Force).
- **MITRE ATT&CK** — Catálogo público de comportamentos de atacantes.

:::caution
O motor_regras_local.py é um SIMULADOR didático: valida o YAML no formato do repositório Azure-Sentinel, roda a query no Kusto real e aplica limiar e agrupamento. Ele NÃO é o Microsoft Sentinel.
:::

## Laboratório guiado

Todos os comandos rodam a partir da pasta raiz do [repositório do curso](https://github.com/bfrpaulondev/curso-sentinel).

### Passo 1

Gere o login suspeito (sintético).

```bash
python3 labs/m4/login_suspeito.py
```

**Saída esperada** (execução real):

```text
9 eventos sintéticos inseridos em SigninLogs (marina.lopes, IP 198.51.100.99, RU)
```

### Passo 2

Rode a regra de login suspeito.

```bash
python3 labs/m4/motor_regras_local.py labs/m4/regras/login_suspeito.yaml
```

**Saída esperada** (execução real):

```text

▶ Regra: Loja Pixel - Sucesso após várias falhas, de país incomum  [Scheduled, a cada 10m, olhando 1h]
  ✓ YAML válido • MITRE: InitialAccess, CredentialAccess / T1078, T1110
  ⚠ 1 alerta(s)
  [INCIDENTE] INC-089D3A: 1 alerta(s) • entidades: Account=marina.lopes, IP=198.51.100.99

Total: 1 incidente(s) → incidentes.json
```

### Passo 3

Veja a validação recusar um MITRE errado.

```bash
python3 labs/m4/motor_regras_local.py labs/m4/exemplos/mitre_errado.yaml
```

**Saída esperada** (execução real):

```text

▶ Regra: Loja Pixel - Força bruta na API de login  [Scheduled, a cada 5m, olhando 15m]
  ✗ YAML inválido: tática inválida: AcessoCredenciais; técnica inválida: T111

Total: 0 incidente(s) → incidentes.json
```
