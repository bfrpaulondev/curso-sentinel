Mini-lab: alerta no Sentinel → Logic App → ticket no Jira

Este é o exemplo concreto para contar na entrevista: “montei um playbook que, quando o Sentinel cria um incidente, abre um ticket no Jira via API e devolve o número do ticket para o incidente”.

O que é real aqui

O código abaixo usa as APIs oficiais (conector Microsoft Sentinel do Logic Apps e a REST API v3 do Jira Cloud). A parte do Jira você testa de verdade com uma conta gratuita do Jira Cloud. A parte do Azure precisa de uma assinatura sua — este curso não simula o portal.

O fluxo

Seção intitulada “O fluxo”

Termos:

  • Automation rule — regra do Sentinel que decide quando rodar um playbook.
  • Logic App — serviço do Azure de fluxos visuais; um playbook do Sentinel é uma Logic App.
  • Identidade gerenciada — uma “conta” que o Azure dá para a Logic App, sem senha guardada.
  • Key Vault — cofre de segredos do Azure.

Passo 1 — Testar a API do Jira na sua máquina

Seção intitulada “Passo 1 — Testar a API do Jira na sua máquina”

Crie um token em id.atlassian.com → Segurança → Tokens de API. Nunca coloque o token no código: use variáveis de ambiente.

Passo 2 — Script Python idempotente (o mesmo raciocínio do playbook)

Seção intitulada “Passo 2 — Script Python idempotente (o mesmo raciocínio do playbook)”

Rode duas vezes: na segunda ele devolve a mesma chave em vez de criar outro ticket. É isso que você conta como “idempotência”.

Passo 3 — O playbook (definição da Logic App)

Seção intitulada “Passo 3 — O playbook (definição da Logic App)”

Trecho da definição (workflow.json) com as três ações principais. O gatilho é o do conector Microsoft Sentinel (“Quando um incidente do Microsoft Sentinel é criado”).

Pontos de segurança que você fala em voz alta na entrevista:

  • Token no Key Vault, lido por identidade gerenciada (sem senha no fluxo).
  • secureData esconde o token e o cabeçalho do histórico de execuções.
  • Tudo por HTTPS; retryPolicy exponencial para falhas temporárias.
  • A Logic App recebe só o papel Microsoft Sentinel Responder no workspace (para comentar), e só Key Vault Secrets User no cofre.
  • O label inc-<número> permite checar duplicados (idempotência).

Passo 4 — Ligar ao Sentinel

Seção intitulada “Passo 4 — Ligar ao Sentinel”
  1. Sentinel → Automação → Criar regra de automação.
  2. Gatilho: Quando o incidente é criado; condição: severidade Alta ou Média.
  3. Ação: Executar playbook → escolha a Logic App.
  4. Dê ao Sentinel permissão de executar playbooks no grupo de recursos (Configurações → Permissões do playbook).

Como contar isso em 30 segundos

Seção intitulada “Como contar isso em 30 segundos”

“Montei um playbook que, quando o Sentinel cria um incidente de severidade média ou alta, abre um ticket no Jira pela REST API e comenta o número do ticket no incidente. O token fica no Key Vault, lido por identidade gerenciada, tudo por HTTPS, com retry e checagem de duplicados. É o mesmo padrão de idempotência e retries que usei numa sincronização de mais de 5.000 operações por dia.”
